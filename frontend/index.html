AI Inference Accelerator — PyTorch Model to Optimized JSON

The AI Model Lifecycle: Training to Inference

AI models have two main phases:
1. Training (Learning): The model studies data to learn patterns (requires massive GPUs, high memory to track gradients, and parameter updates).
2. Inference (Running): The trained model is deployed to run predictions on new data (demands low latency, speed, and low power).
Where this tool helps: Right at the transition to Inference. We optimize the graph structure specifically to reduce its resource footprint before deployment.

Why Download the DAG JSON? (No-Python Deployment)

Most edge devices (like smart cameras, mobile chips, or cars) have very limited hardware resources and cannot run Python. Python requires a large software stack, consumes excessive CPU overhead, and has threading locks that slow down execution.
The downloaded JSON is a language-independent blueprint. It allows developers to load the optimized model directly into highly efficient C++ runtimes (LibTorch) or edge compiler frameworks (TVM, OpenVINO) to run predictions at maximum speed using **zero Python**.

How It Works

⚙️

1. Graph Tracing & Mapping

Think of a neural network as a factory assembly line. Each operation (like a Convolution) is a worker. We map this flow as a Directed Graph (DAG) to see exactly how data moves from worker to worker.

📅

2. Topological Scheduling

We use Topological Sorting (Kahn's BFS algorithm) to schedule execution. This ensures workers only run when all their dependencies are ready, providing a deadlock-free, sequential checklist.

⚡

3. Operator Fusion

Usually, workers save intermediate results to main memory (RAM/VRAM) before the next worker reads them back. Fusing operations (like Conv-BN-ReLU) lets the processor calculate them together in-register. By skipping memory writes, we eliminate temporary buffers, saving memory (preventing Out-of-Memory crashes) and speeding up execution.

How It Works — Visual Guide

⚡ Kahn's BFS Topological Sort — Why Order Matters

Real models have branches (like ResNet skip connections). A node can only run when all its inputs are ready. Kahn's algorithm tracks each node's in-degree (number of unprocessed parents) and uses a queue to schedule nodes whose in-degree reaches 0.

Step Queue Action Output Order
1 x in-deg(x)=0 → enqueue. Pop x, decrement Conv & Add x
2 Conv Conv in-deg→0. Pop Conv, decrement BN x Conv
3 BN BN in-deg→0. Pop BN, decrement ReLU x Conv BN
4 ReLU ReLU in-deg→0. Pop ReLU, decrement Add (now 0!) x Conv BN ReLU
5 Add Add in-deg→0 (both parents done). Pop Add, decrement Out x Conv BN ReLU Add
6 Out Out in-deg→0. Pop Out. Queue empty → done! x Conv BN ReLU Add Out
💡 Key insight: Add has in-degree 2 (Conv branch + skip connection). It stays locked until both paths complete. Without topological sort, a naive schedule could try to run Add before ReLU finishes — causing a crash.

🔗 Operator Fusion — Eliminating Memory Traffic

Each GPU operation normally writes its result to slow VRAM/RAM, then the next operation reads it back. Fusion keeps data in fast GPU registers, skipping the slow memory entirely.
